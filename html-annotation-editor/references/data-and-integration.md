# 数据与接入

## 标准注记清单

自动生成和默认简洁导出使用以下五列。清单文件生成后直接解析原型并创建注记，不增加确认环节。参考 Axhub 的稳定标识和定位机制，但技术字段只在内部数据中维护。

```markdown
# 注记清单

| 编号 | 菜单路径 | 目标区域 | 注记类型 | 注记内容 |
| --- | --- | --- | --- | --- |
| 1 | 项目管理 / 项目列表 | 筛选区域 | 交互逻辑 | 项目名称和状态组合查询。<br>重置清空条件。 |
```

- 编号从 1 开始连续，菜单路径沿用真实层级，以 ` / ` 分隔。目标区域写可读名称，如“查询按钮”“项目列表分页栏”，不写 ID、CSS 选择器或源代码。
- 类型仅四类，内容保持业务边界。资料未体现的规则在正文说明，不猜测为既有功能。自动清单和简洁导出不含注记 ID、页面 ID、页面状态、定位选择器、来源依据、确认状态，也不通过隐藏列、第二个工作表或附注重新导出它们。
- 表格内换行写 `<br>`；原文竖线、反斜杠、反引号写 `&#124;`、`&#92;`、`&#96;`，`&`、`<`、`>` 写 `&amp;`、`&lt;`、`&gt;`。先转义原文再转换换行；原文字面 `<br>` 写为 `&lt;br&gt;`。
- 清单不承担机器定位功能。技能在生成清单后自动检查原型，将菜单路径、目标区域解析到页面上下文和唯一目标，生成临时内部 JSON；不是让用户再填一份技术清单。内部 `notes` 顺序与清单一致，每条含 `id`、`selector`、`menuPath`、`targetArea` 及必要的 `pageId`／`context`／`fingerprint`，自定义菜单放 `menus`。已有注记复用原 ID，新注记生成 UUID。相同页面相同目标可有多条注记，须结合原始数据维护稳定身份，不只按显示编号认定同一条。
- 调用 `inject.py 原始.html 注记清单.md 新文件.html --mapping 内部定位.json`。脚本校验五列表头、连续编号、内部数据条数及每条的菜单路径／目标区域；类型和正文从清单覆盖到内部数据。缺少定位映射时明确报错，不伪造 selector。也可直接传入按清单合成的最终 JSON；业务内容必须与清单逐项一致。
- 用户导出的五列清单再次用于原型时，同样由技能重新解析原型并生成内部定位数据，不能声称只有清单就能恢复任意原型的 DOM 定位。生成结束删除临时映射文件，保留清单与新 HTML；HTML 内部仍保留实际定位数据。
- 导出类型默认“简洁”（五列）；选择“详细”时，在五列后依次追加注记ID、页面ID、页面状态、定位选择器、来源依据，共十列。MD 和 Excel 均支持。页面状态直接读取 context，缺省以 `*` 表示通用；无可靠页面归属或来源时对应字段留空，确认状态不导出。Excel 使用纯文本单元格，超长内容提示改用 Markdown，不截断；空清单仍含所选类型的表头。
- 详细导出用于核查和定位追溯。当前 Markdown 注入接口仍读取标准五列清单及内部定位映射；需要重新生成时由技能将详细表前五列作为标准清单，其余字段校核后转为内部定位数据，不要求用户手工改表。

## 最小数据

```json
{
  "version": 1,
  "notes": [
    {
      "id": "note-filter",
      "type": "交互逻辑",
      "body": "按姓名和状态组合查询，重置恢复默认条件。",
      "selector": "#filters",
      "context": "",
      "source": "原型：applyFilters() 与 resetFilters()"
    }
  ]
}
```

| 字段 | 约定 |
|---|---|
| version | 必须为整数 1 |
| notes | 数组，空数组表示仅安装编辑能力；数组顺序对应 1…N。编辑可在 1…N 内改号，以移动数组元素实现，中间编号补齐／顺延，稳定 id 不变；新增上限 N+1，编辑上限 N |
| id | 必填，非空、全文件唯一，重排时保持不变；新增手动注记生成 UUID |
| title | 仅兼容旧数据，不再要求、生成或展示；编辑保存时移除 |
| body | 必填纯文本；手动输入正文最多 20,000 字符 |
| type | 新增／编辑保存必选：`字段说明`、`交互逻辑`、`业务规则`、`修改原型`。“修改原型”为待产研后续修改的事项，用红色标识，不表示已有功能需求；其余类型使用橙色标记。颜色由类型派生，不另存颜色字段。旧数据可缺省，显示“未设置类型”，不自动归类；再次编辑保存时需选择。类型随清单导出及重新注入保留 |
| selector | 必填 CSS 选择器，在指定状态唯一匹配宿主元素；不指向标注 UI |
| context | 可省略，表示所有上下文；`*` 也表示通用，其他字符串严格匹配当前上下文 |
| pageId | 可选，所属菜单的稳定 id；自动接入自定义路由时填写，手动选区时自动关联。优先于 context 和目标容器推断；失效时归入“未匹配页面” |
| targetArea / menuPath | 可选纯文本，分别保存清单中的可读目标区域、菜单层级路径，不作注记标题 |
| confirmationStatus | 仅兼容旧数据；新数据不生成、不参与接入判断，MD／Excel 不导出此列 |
| source | 可选，来源文字，仅作为追溯数据保留；内容浮窗不展示来源，不执行链接或脚本 |
| fingerprint | 可选 `{ "tag": "button", "text": "查询" }`；文字先压缩空白、trim、截取前 100 字符。通用手动选择自动记录，变化后标为未匹配 |
| base | 由注入脚本写入，不手写：原始 UTF-8 HTML 的 Base64。脚本重新注入时使用它重建源码，避免动态 DOM 重复初始化 |

不要把行号序号、浮层屏幕坐标作为永久身份。`selector` 失效、重复、隐藏或上下文不匹配时保留数据，在目录中提示，允许进入编辑重新选择位置。

## 自动菜单识别与映射

普通 DOM 导航由运行时自动读取，锚点或 `aria-controls` 映射内容容器，`data-page`／`data-route` 映射上下文，嵌套列表保留菜单层级。按目标所在的最小菜单内容容器归组，编号始终使用原 notes 顺序。外部链接不作为当前 HTML 页面目录。

仅由 JavaScript 函数驱动的菜单、复合上下文、动态渲染页面：接入技能须读取真实菜单和路由源码，**自动生成**顶层 `menus` 数组，不把通用运行时启发式识别描述成万能支持。例如：

```json
"menus": [
  {"id": "projects", "label": "项目管理"},
  {"id": "project-list", "label": "项目列表", "parentId": "projects", "context": "projects:list", "selector": "#projectArea"}
]
```

`id` 全局唯一、稳定，`label` 来自真实菜单，`parentId` 引用父菜单，不能循环；纯分组节点只需 id／label。`selector` 可选，定位唯一页面容器；`context` 可选，严格匹配 `htmlAnnotationContext()`。`pageId` 指向菜单 id；页面身份与更细的弹窗／页签 context 可独立。自动注记应在生成时关联 pageId，尤其是不同页面复用 selector 的情况。手动添加及重新选择位置时自动识别归属；不确定时保留未匹配状态。

显式 menus 同 id 合并并覆盖其提供的字段，未提供的 selector／context 仍保留 DOM 发现结果，其他条目合并；若要覆盖运行时发现的条目，沿用 `target:` 加选择器、`route:` 加上下文的 id，避免双份菜单。使用自定义映射时需包含完整父链。缺失 pageId 时先匹配唯一 context，再通过唯一目标及内容容器推断；非空未知 context 不按复用 selector 猜测归属。没有菜单时单页回退到 document.title，有菜单的未归属注记统一列入“未匹配页面”。不要按标签文字合并同名页面。

菜单映射和 pageId 在脚本新生成的 HTML 中保留；展开／收起只存内存。既有 title 可读取但不展示；条目固定为“序号＋类型”和完整正文，无标题输入或摘要标题。

## 目录跳转适配

目录点击注记时先导航所属页面，再等待目标出现并滚动到目标、打开内容浮窗；点击页面分组展开时导航并展示该页首条注记，无注记的页面仍可切页。纯父级分组只折叠／展开。

运行时复用 `discoverMenus` 识别到的宿主导航元素，不执行任意正文脚本或猜测业务按钮。对于配置菜单、详情页或自定义 JS 路由，技能必须读取真实渲染入口并在新副本源码中提供以下适配，自动支持目录跳转：

```js
window.htmlAnnotationNavigate = async (pageId, note) => {
  // 使用目标原型中真实存在的路由映射与函数，不可原样复制示意变量名。
  const page = annotationRoutes[pageId];
  if (!page) throw new Error('未找到对应页面');
  await navigatePage(page);
  // 如注记属于特定记录、页签或弹窗，在此恢复其实际上下文；不调用新增、提交、删除动作。
};
```

适配器接收稳定页面 ID 与注记；无注记的页面点击会传入包含菜单 context 的对象。同步切页可直接返回，异步应在对应页面渲染完成后 resolve；失败应 throw。运行时随后最多等待 2 秒检查目标，超时仍显示注记正文并说明目标不可见。已有表单未保存时阻止目录切页；新增点击覆盖旧内容定位请求。把适配放在副本的源码中以便再次生成时保留，不修改原始业务 HTML。

## 自定义上下文

默认 `location.hash`，不使用文件路径作为身份，因此生成文件改名后仍可定位。没有 hash 的单页原型需要按真实宿主状态提供函数；下面仅是示意，变量名必须从目标代码读取：

```js
window.htmlAnnotationContext = () => `${currentPage}:${activeTab}:${openModal || 'none'}`;
// 在实际渲染结束位置调用，尤其是状态变化但 DOM 未变化的路径。
window.HTMLAnnotationEditor?.refresh();
```

把适配代码放在注入前的 HTML 源码中，确保它属于嵌入的 `base`。对于全局导航等跨页区域，使用 `context: "*"`。一项标注若服务多个状态，可使用宿主添加的稳定属性与通用上下文；不要复制同一 ID。

自动接入时尽量为模板里的功能区域增加稳定 ID／属性。仅在当前 DOM 上加属性不会持久化到原始 HTML；必须修改模板或持久化渲染后绑定逻辑。动态表格中的单条记录用业务主键定位；文字指纹不适合作为会频繁变化的区域唯一身份。

## 迁移 Axhub

迁移前保留原文件，所有操作在新副本完成。检查全部旧加载与创建位置，而不仅是脚本文件名。

1. 从 `AnnotationSourceDocument.data.nodes` 提取 title／annotationText、locator 与 pageId；长文从 markdownMap 取出，按纯文本保留。如果用户要求 Markdown 格式渲染，明确这是单独扩展，不把 HTML 直接写入浮层。
2. 根据旧顺序形成 notes，旧 ID 保持为稳定 ID，新显示编号连续 1…N。迁移清单记录“旧 ID → 新编号”，旧目录 route／markdown／controls 不属于页面 marker 数据，不能伪装迁移成功。
3. 逐项核查 locator 在真实渲染状态唯一命中，把 old pageId 与新 context 对齐。保留必要的宿主定位适配逻辑，但改为新刷新入口。
4. 在副本中移除旧 source、旧 viewer 创建与仅用于旧 UI 的加载块；保留业务代码及仍被其他功能引用的资源。用户若要求迁移目录文档／状态控件，先确认映射方式或补充实现。
5. 运行注入器，打开副本验证没有双重浮窗与残留标记。

注入器检测到已知旧 Axhub 接入时会停止，避免自动删除不明宿主代码。已有本技能文件再次注入时使用嵌入的原始源码，避免包裹层逐次膨胀；更新用的 JSON 应先从现有 `hae-data` 合并，不能用空数组覆盖用户手工编辑。

## 文件保存边界

添加、修改和删除经单条确认即更新当前页面、内嵌数据和浏览器 `localStorage`，没有本轮草稿、额外保存按钮或批量回滚。本地存储键由内嵌原始源码 `base` 生成，重新打开时优先恢复合法数据；损坏数据回退到 HTML 内嵌注记。控制面板不提供“保存 HTML”，也不自动写回磁盘源文件；导出 MD／Excel 清单用于跨浏览器、跨设备或文件交付。只在单条输入尚未确认，或已改动数据自动保存失败时保留离页提醒。多个窗口没有实时协同，不把当前业务表单临时输入当成原型源码。

宿主如有外部 CSS／JS／图片，输出文件仍需原路径资源，除非另行内联。严格 CSP、特殊模板语法、非 UTF-8 HTML 应先按宿主要求适配。通用脚本面向正常 UTF-8 HTML，输出另一个路径且不覆盖已有文件。
